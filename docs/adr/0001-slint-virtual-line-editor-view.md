# 0001: 自繪編輯器元件採用 Slint 可見行虛擬渲染與固定字元格網

為了擺脫 Slint 內建 `TextEdit` 無法支援大檔案虛擬捲動、列塊模式與自訂語法著色的限制，我們決定採用 Slint 原生宣告式可見行列表（`for line in visible-lines`）結合 Rust 核心管理的「固定字元格網（Character Cell Grid）」架構。

## Context

Slint 內建的 `TextEdit` 是一個黑盒子，無法存取內部選取模型，亦無法進行虛擬捲動，若整份大檔案載入會造成嚴重的記憶體與渲染負擔。此外，跨平台等寬字型在混排 CJK 中日韓字元時，系統預設 Fallback 字型寬度往往不是西文字體的精確 2 倍，導致依賴純文字渲染時游標累積漂移，無法在未來的列塊模式下達到嚴格垂直對齊。

## Decision

1. **可見行虛擬渲染**：Rust 核心根據視窗目前滾動行數與可視行數（`Viewport`），每次僅切片產出當前畫面可見的 30～50 行結構體傳遞給 Slint 繪製，Slint 內以 `FocusScope` + `TouchArea` 捕捉鍵盤與滑鼠事件。
2. **固定字元格網（Character Cell Grid）**：在核心以嚴格欄位寬度（半形 1 欄、全形 2 欄、Tab 展開為 4 欄對齊）計算視覺座標 `VisualColumn`，保證游標、選取區反白與滑鼠點擊判定永不漂移，並為 Phase 4 列塊模式奠定堅實基礎。

## Consequences

- 編輯器保有跨平台原生 Slint 字型抗鋸齒與流暢度，同時具備千萬行大檔虛擬捲動的效能。
- 鍵盤事件、游標閃爍、字元輸入與選取拖曳皆由 Rust 核心邏輯直接控制，使編輯行為容易撰寫完整的單元測試進行覆蓋。
